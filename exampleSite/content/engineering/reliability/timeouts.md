---
title: Таймауты и повторы
description: Как ограничить ожидание и повторять временные ошибки с контролируемой задержкой.
weight: 10
---

Таймаут ограничивает время, которое запрос может занимать на одном участке системы. Общий дедлайн запроса должен включать сетевое подключение, ожидание ответа и обработку результата. Если каждый внутренний вызов получает независимый таймаут, сумма этих ожиданий может превысить время, которое разрешил внешний клиент.

Для повторов часто используют экспоненциальную задержку:

$$
t_n = \min(t_{max}, t_{base} \cdot 2^n)
$$

где $n$ — номер повтора, а $t_{base}$ и $t_{max}$ задают нижнюю и верхнюю границы. Чтобы множество клиентов не повторяло запрос одновременно, к задержке добавляют случайный jitter:

$$
t'_n = \operatorname{random}(0, t_n)
$$

Повторяйте только ошибки, которые могут исчезнуть сами: временную недоступность, разрыв соединения или ответ `429` с учётом `Retry-After`. Ошибку валидации и отказ в доступе повторять бессмысленно. Для изменения состояния дополнительно нужна идемпотентность операции.

```python
import random


def retry_delay(attempt: int, base: float = 0.2, maximum: float = 5.0) -> float:
    limit = min(maximum, base * (2 ** attempt))
    return random.uniform(0, limit)
```

У повтора должны быть пределы: число попыток, общий дедлайн и лимит нагрузки. Если downstream-сервис уже перегружен, бесконтрольные повторы превращаются в усилитель отказа. Метрики должны отдельно показывать исходные ошибки, повторы и успешные ответы после повтора.
